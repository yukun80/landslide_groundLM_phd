# 理解区域怎样算出来

[返回上级](../README.md)

打开 [pixel_mask_decoder.py](../../../Xiaomi-Lens-0-raw/src/xiaomi_lens/model/pixel_mask_decoder.py)，先找 `PixelMaskDecoder.forward`，读完再看构造函数与 `PatchSelfAttention`。文件开头的加速兼容部分可以最后读。

| 步骤 | 实际工作 | 为什么需要 |
|---|---|---|
| 目标转换 | 将区域处的文字状态变成较短的目标表示 | 得到与像素特征相同的宽度 |
| 图片转换 | 把视觉特征投影到处理宽度 | 让后续层接收尺寸一致的表示 |
| 小块交流 | 图片小块之间进行一次自注意力 | 一个位置可结合整张图的信息 |
| 恢复网格 | 从小块列表变回二维布局 | 后续要按真实空间位置放大 |
| 学习放大 | 两次高宽各乘 2 的转置卷积 | 从粗网格生成更细的像素表示 |
| 逐位置评分 | 目标表示与像素表示逐项相乘再求和 | 每个目标得到自己的一张分数图 |
| 固定放大 | 高宽再各乘 4 | 输出达到模型图片画布尺寸 |

### 3.3 用小数字读懂形状

代码中的 `B, K, H, W, C` 只是维度名字。`B` 是这次处理的组数，`K` 是区域数，`H/W` 是高宽，`C` 是每个位置存多少种信息。二维图片只有高宽，但内部每个位置可存很多个数字。

假设一组里有两个目标，图片小块网格为 2 行×3 列，小块边长为 16：

1. 目标输入是 `1×2×D`；图片输入是 `1×6×V`。`D/V` 分别是文字与视觉表示的宽度，不是图片大小。
2. 图片经过注意力并放回二维网格，变为 `1×D×2×3`。
3. 两次学习放大后是 `1×C×8×12`；两个目标查询是 `1×2×C`。
4. 沿 `C` 相乘求和，得到 `1×2×8×12`。
5. 固定四倍插值后得到 `1×2×32×48`，即两张高 32、宽 48 的区域分数图。

这里的 16 倍对应当前实现的小块边长，不能任意改成别的数还期待尺寸都对齐。`sigmoid` 把原始分数换成 0～1 的概率；原始分数 0 对应概率 0.5。训练计算损失前不要自行先硬切成 0/1。

自测：这段代码是不是先把目标文字与图片做交叉注意力，再画区域？**不是。当前解码器先做图片小块之间的自注意力，最后用目标与像素表示的点积评分。**
