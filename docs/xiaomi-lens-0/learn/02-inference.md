# 跟着一次真实使用走

[返回上级](../README.md)

打开 [infer.py](../../../Xiaomi-Lens-0-raw/infer.py)，先找最下面的 `main`。先读里面的调用顺序，再跳到这些函数，不必先研究所有命令行选项。

| 顺序 | 去哪里看 | 这一步解决什么 | 看懂后的自测 |
|---|---|---|---|
| 1 | `load_model_and_processor` | 读入已学好的参数，以及对应的图片文字处理规则 | 为什么只有源码还不能直接得到可靠预测？因为还需要学好的参数。 |
| 2 | `build_inputs` | 将图片、问题放进对话模板，并转换成数字 | 图片路径是不是模型直接理解的内容？不是，图片会被读取并转成小块特征。 |
| 3 | `generate_completion` | 生成新的回答，保留特殊符号和真实编号 | 返回的编号包括问题吗？此函数截取的是新生成部分。 |
| 4 | `split_answer_content` | 将思考内容与最终答案分开 | 思考里有两个区域，答案有一个，应展示几个答案区域？一个。 |
| 5 | `run_forward` | 用完整序列再计算，取得所有区域分数 | 第二次计算为什么还要图片？区域分支需要对应图像特征。 |
| 6 | `visualize_pixel_mask` | 转成概率、给选中像素着色并保存 | 输出尺寸一定等于原照片吗？不是，这里画在模型处理画布上。 |

[constants.py](../../../Xiaomi-Lens-0-raw/src/xiaomi_lens/constants.py) 只需顺手看一眼：它放特殊符号和默认生成长度；画图颜色在 infer.py 内。`__init__.py` 是包的入口，不是算法的第一步。

实际对照检查使用了仓库附带的一张图片和问题“RIGHT VASE”。它展示了图片→文字→一个目标区域的完整流程，记录和输出图见检查结果。这个例子只用于验证注释前后行为一致，不代表已重新评测模型准确率。
